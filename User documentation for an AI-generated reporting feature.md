# User Documentation for an AI-Generated Reporting Feature

**Helping users understand, use, and verify AI-generated reports.**


## Overview

A SaaS platform launched a feature that generates reports with AI from data in users' connected apps. Users needed to understand how to set up and use the feature, which data a report draws on, and what to check before relying on or sharing the result.

**Focus:** Clear documentation of the AI feature's limitations and review steps, alongside onboarding and troubleshooting.

**Approach:** Feature walkthrough and testing → user task mapping → limitations and failure cases → help-centre structure.


## Documentation Deliverables

| Deliverable | What it gave users |
|---|---|
| **Onboarding guide** | A clear path from first use to generating a first report |
| **How it works page** | A plain-language explanation of what the feature does and which data it uses |
| **Limitations and review instructions** | Guidance on where reports can be wrong and what to check before relying on them |
| **Troubleshooting and FAQ** | A route for diagnosing incomplete, unexpected, or incorrect output |
| **Help-centre articles and release notes** | Task-based content that users and support could find and reuse |


## Outcome

Users and the support team had documentation covering feature setup and use, data sources, limitations, and review steps from launch.
